## TRK-8 · Event envelope v1 and the six initial event types

Labels: `type:feat`, `area:sdk`, `size:M` — **this is the M0 loop proof: the owner does not open an editor.**

Use the `new-event-type` skill.

**Acceptance criteria**
- `packages/event-schemas` exports a zod `EnvelopeV1`: `event_id` (uuid v7), `type`, `version`, `occurred_at`, `received_at?`, `attribution_key`, `session_id`, `seq` (int ≥ 0), `user_id?`, `app_id`, `source` (`client`|`server`), `trust` (`unverified`|`signed`), `context` {url, referrer?, utm_source?, utm_medium?, utm_campaign?, utm_term?, utm_content?, click_ids?, ua?, ip_trunc?}, `payload`.
- Payload schemas + registry for `SessionStarted`, `PageViewed`, `ElementClicked`, `CustomEventTracked`, `Identified`, `ConversionRecorded` (the latter requires `conversion_id`, `value?`, `currency?`).
- Rule enforced by schema: `source=client` ⇒ `trust=unverified`.
- Fixtures: ≥ 2 valid and ≥ 2 invalid per type; contract tests green.
- Inferred TS types exported; `parseEvent(unknown)` returns a typed result or a zod error.
