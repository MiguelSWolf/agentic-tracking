# M0 retro

- Date: 2026-11-23
- Scope: M0 (foundations and agent workflow), 20 issues, including TRK-5 … TRK-28

## Outcome

M0 set out to prove the agentic loop: plan (G1), implement, review (G2), audit (G4) on a scaffolded
repo. It did. 10 agent PRs were opened and 10 merged, with a median of 0 `@claude` rounds. The
process gaps are in 14 finding files. This is the first retro, so there is no earlier trend.
No Linear `source:finding` issue exists for M0: that capture started with
[#31](https://github.com/MiguelSWolf/agentic-tracking/pull/31), near the end of the milestone, so nothing was imported.

## Patterns and rule changes

- **A. Tests and examples that pass even when the behaviour is wrong.** Evidence: #23 (the `parseEvent`
  conversion test skipped its assertions on a wrong discriminator), #19 (the TEST-17 example only checked the end
  state, TEST-16 left out shuffled batches), #18 (the TS-17 example rethrew a non-`Error`, against NODE-01).
  → Rule in `issue-flow` implement step 3 and a check in `review-pr`. Exact text in the PR body.
- **B. Docs that claim more, or less, than the check enforces.** Evidence: #23 (spec implied ISO 4217
  validation, the code checks the format only), #18 (incomplete Biome severity note, overstated `erasableSyntaxOnly`
  coverage for TS-08). → Rule in `issue-flow` and an ADR-0012 check in `review-pr`. Exact text in the PR body.
- **C. `@claude` iteration mechanics.** Evidence: F-002, F-004, #18, #19, #24. Already turned into rules by #26 and #30.
  No new change. Check the effect in the M1 retro.
- Not recurring: the metric edge cases on #24 (one PR). No rule change.

All target files are protected, so the owner applies A and B.
