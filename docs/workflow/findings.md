# Findings: how process gaps are captured

A **finding** is a gap in the process or tooling found while running the agentic loop: a gate that
did not fire, a command the agent could not run, missing context, a review tool that skipped a PR.
It is not a product bug, which is a normal Linear issue. Findings feed the milestone retro, which
records a decision for each one. Calibration of the gates themselves: [ADR-0011](../adr/0011-calibration-metrics.md).

## Where they live

One file per finding, in `docs/retros/<milestone>/findings/F-NNN-<slug>.md`. Using one file each
means two PRs can add findings at the same time without conflicts. The index
(`docs/retros/<milestone>/findings/README.md`) is generated by `pnpm findings:index`, and CI checks
that it is up to date.

```markdown
# F-NNN: <what went wrong, in one sentence>

- Status: open | in progress (TRK-n) | fixed (#PR) | accepted
- Area: <gate, CI, agent context, review, code standards, …>
- Source: agent | workflow | owner
- Found: YYYY-MM-DD
- Evidence: <PR, run or issue links>

## What happened

## Proposed fix
```

Get the next ID with `node scripts/findings-index.mjs --next <milestone>`.

## How they are captured

| Source | How |
| --- | --- |
| An agent hits a gap during a run: a denied command, missing context, a workaround | The agent adds the finding file **in the same PR**, following its skill, and lists it in the PR body. |
| An agent run fails or is degraded: the job failed, Claude stopped early (for example at the turn cap), or a tool call was denied | The last step of `agent-implement` and `agent-pr-iterate` runs `scripts/run-findings.mjs` on the run's execution file. If it finds a signal, `scripts/linear.mjs finding` opens a Linear issue labelled `source:finding` with the run link. The same signals on the same target add a comment to the open issue instead of creating a duplicate. The retro imports these issues as files. |
| The owner or a reviewer notices something | Add the file in a PR. |

## How they are closed

The milestone retro ([`retro` skill](../../.agents/skills/retro/SKILL.md), run on the milestone issue labelled `type:retro`) reads every finding of the milestone together with the
calibration metrics (`pnpm agent:metrics`) and the audit report. It decides for each finding:

- **fix:** open a Linear issue and set `Status: in progress (TRK-n)`;
- **accept:** set `Status: accepted` and give the reason in the file;
- **already fixed:** set `Status: fixed (#PR)`.

No finding leaves a milestone without a decision.
